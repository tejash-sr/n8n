PER-NODE STICKER (the `notes` field on every non-sticky node)
─────────────────────────────────────────────────────────────
Every functional node carries a one-paragraph `notes` field that names
the node and explains its purpose — the "per-node sticker" requested in
the user's brief. When you hover the node in the n8n UI, this text
appears as a tooltip. Examples:

  Config            → "Deployment-level switches every downstream node
                       reads from. Keep prompts in the Prompts node,
                       not here."
  Prompts           → "Single source of truth for both system prompts.
                       Edit prompts here, not inside the AI nodes."
  Compute preview   → "Second-pass Set node. Computes body_preview from
                       the just-computed body_clean — lives in its own
                       node because n8n does not guarantee evaluation
                       order of sibling fields inside a single Set node."
  Wait for draft id → "Hand-off boundary so $node['Create Gmail draft']
                       .json.id is populated before Slack templates it
                       into the Open-draft-in-Gmail button."
  Log unknown       → "Switch fallback target. Captures the rare case
   category to errors  where the LLM returns a category outside the 4
                       allowed enums."
