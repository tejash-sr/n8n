# Contributing

Internal Grootan Technologies training material. Here's how to make changes safely.

## Branching

- `main` — protected. Only PRs from `genspark_ai_developer` or other feature branches.
- `genspark_ai_developer` — AI-developer scratchpad and feature integration.
- `feature/<short-desc>` — one feature per branch. Squash-merge into `genspark_ai_developer` (then onto `main` via PR).

## Required checks before every push

```bash
python3 scripts/check_no_send.py        # MUST exit 0
python3 scripts/validate_workflows.py   # MUST exit 0
```

A GitHub Actions workflow that re-runs both validators on every push/PR is
recommended (and ready to drop in — see the "CI snippet" at the bottom of this
file). It needs the repo's GitHub App to have the `workflows` permission first.

## Editing the workflow

**Do not** hand-edit the `workflows/*.json` files. They are generated by `scripts/build_workflows.py`.

To change a prompt, a node name, or the wiring:

1. Edit `scripts/build_workflows.py` (or the markdown prompt files if you only want to change prompt content).
2. Run:
   ```bash
   python3 scripts/build_workflows.py
   python3 scripts/check_no_send.py
   python3 scripts/validate_workflows.py
   ```
3. Commit the rebuilt JSONs **and** the source edit in the same commit.

This keeps `git diff` small and reviewable.

## Commit message style

Conventional commits, scoped by phase or area:

| Type    | When to use                                              |
|---------|----------------------------------------------------------|
| `feat`  | New phase, new node, new prompt                          |
| `fix`   | Bug in workflow JSON or script                           |
| `chore` | Tooling, scaffolding, dependency bumps                   |
| `docs`  | Markdown-only changes                                    |
| `refactor` | Restructuring without behaviour change                |
| `test`  | Test fixture / accuracy improvements                     |

Example: `feat(phase-4): tighten reply prompt to forbid pricing mentions`.

## Secrets policy

- **Never** commit `.env`, `credentials.json`, `token.json`, OAuth tokens, API keys, or service-account JSON files. `.gitignore` blocks the common patterns; `scripts/validate_workflows.py` greps for `sk-`, `xoxb-`, `GOCSPX-`, etc.
- `.env.example` may contain only placeholders.
- Workflow JSONs may contain credential **references** (`{id, name}`) but never values.

## Pull request checklist

- [ ] `scripts/check_no_send.py` passes
- [ ] `scripts/validate_workflows.py` passes
- [ ] If you changed a prompt, you also re-ran `build_workflows.py` and committed the regenerated JSON
- [ ] If you changed an acceptance criterion, you updated `docs/EVALUATION_RUBRIC.md`
- [ ] Screenshot in `docs/screenshots/` updated if the canvas changed visibly
- [ ] One concern per PR (don't bundle Phase 3 + a Phase 5 prompt tweak)
- [ ] Loom or short description of what you tested

## CI snippet (drop in once the `workflows` permission is granted)

Save as `.github/workflows/validate.yml`:

```yaml
name: Validate workflows
on:
  push:
    branches: [main, genspark_ai_developer]
  pull_request:
    branches: [main]
jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - run: python3 scripts/check_no_send.py
      - run: python3 scripts/validate_workflows.py
      - run: python3 scripts/build_workflows.py
```
